# 长期日记与原文召回

在“L3 长期日记”中启用日记功能后，可以分别选择固定时间生成和消息数量触发。固定时间默认开启；消息阈值默认 0，表示关闭。将阈值设为 20，表示当天新增消息累计达到 20 条时生成日记，之后每增加 20 条再生成一个版本。首次生成至少需要 5 条材料。生成过程中收到的新消息也会在任务完成后重新检查。

新版本不会覆盖旧日记。自动上下文只读取每天的最新版本；启用消息阈值时也会读取今天的最新日记，旧版本仍可逐页召回。固定时间任务会为昨天补齐尚未记录的新消息。日期使用服务器本地时区。日记生成需要可用的聊天模型；关闭 L3 后无法手动生成，但仍可读取已经保存的记录。

## 管理员命令

需要 Koishi 权限等级 3，仅操作当前会话。

```text
history.diary                         # 手动生成今天的日记，静默注入
history.diary 2026-10-10 --display     # 生成指定日期的日记并显示结果
history.recall 旅行 -k l3 --display   # 查找 L3 原文，显示并注入
history.recall -k messages -u 123456  # 按发送者召回完整消息，静默注入
history.recall -k l3 -o 6 -n 6       # 继续读取下一页
history.recall -k messages --start 2026-10-01 --end 2026-10-02
```

默认不在聊天窗口显示，召回结果会进入当前会话的观察上下文，在下一次正常心跳时交给 Bot。`--display` 只增加窗口显示，不改变注入内容；它不会强制 Bot 立即回复。

## Bot 工具

- `memory_recall`：按 `kind=messages|l2|l3`、关键词、日期或记录 `id` 读取原文。原始消息可按 `user_id` 筛选。`offset` 和 `limit` 控制分页，每页最多 20 条。
- `conversation_search`：按关键词搜索当前会话的完整原始消息，支持 `offset` 继续读取。
- `l3_diary_generate`：手动生成当前会话的日记，`date` 可省略。返回确切新版本；无新消息或材料不足时标明 `generationStatus=unchanged`，不会把旧日记当作新生成结果。

`display` 默认 false；true 时同时将结果发送到聊天窗口。窗口发送失败会注明显示失败，完整召回结果仍返回给 Bot。跨频道回忆继续使用人物插件中配置好的共同域与 `person_recall`。

## 原文与分页

选中记录的正文保留换行、标签和末尾空白，不再裁为 120 或 4000 字，也不再次总结。来源 ID、平台、频道、时间与发送者随记录返回。L2/L3 返回的是存储摘要或日记原文；要查看此前的实际发言，应使用同日期范围的 `messages` 召回。

`hasMore=true` 表示尚有下一页，使用 `nextOffset` 继续。分页限制的是记录数量，不截断选中记录的正文。单条原文很长时可能超过模型本身的上下文容量，此时应缩小日期或记录范围，不能用再次摘要替代原文。

召回沿用身份纠错过滤和历史清理屏障。历史被清除后，旧召回结果不能重新注入。人物插件此前已经裁剪并保存的旧来源，缺失的正文无法凭空恢复；升级后新保存的来源保留完整正文，也可用核心原始消息记录核对仍保留的内容。
