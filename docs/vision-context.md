# 对话中的图片

开启 `enableVision` 且当前模型组包含声明支持视觉的模型时，主请求会直接携带经过资源服务读取的图片。模型组仍按原有能力声明选择模型；只有文字说明、图片编号或失效资源时，不会把文字请求视为已经看过图片。

图片按以下顺序选择：本次用户消息中的图、明确引用的图、同一会话中同一用户最近发送的图、仍在生命周期内的其他历史图。去重后受 `maxImagesInContext` 限制，保留原有 MIME 白名单和图片处理设置。最近图来源会在上下文软预算裁剪时与当前问题一起保护；其他旧图仍可被裁剪。保护内容超过软预算时沿用原有超预算报告，不增加图片上限。

| 设置                         | 默认值   | 含义                                                                           |
| ---------------------------- | -------- | ------------------------------------------------------------------------------ |
| `imageLifecycleCount`        | 2        | 普通历史图片可参与的成功用户任务次数；同一任务中的工具调用和内部心跳只计一次   |
| `imageFollowUpWindowSeconds` | 600      | 同一用户无引用追问时保留最近图片的时间窗，0 关闭此保护                         |
| `imageFollowUpMaxTurns`      | 4        | 最近图片之后允许的用户消息数量，包含已记录但没有唤醒机器人的消息；0 关闭此保护 |
| `maxImagesInContext`         | 沿用原值 | 单次主请求的图片数量上限                                                       |

上述两项追问设置为 0 只关闭额外近图保留；普通历史图片生命周期尚未用尽时仍可能附图。

当前发图与明确引用优先于普通历史图片的生命周期限制。无引用追问同时受时间窗和消息次数限制，不判断语义上是否仍在讨论图片。同一用户发出新图片后，最近图来源更新为这次图片；不同用户、平台、机器人和会话分别隔离。正在执行的同一用户任务保留其图片，不因连续内部心跳耗尽寿命。

原消息离开短期上下文时，可以通过已有的会话历史读取接口恢复该条来源，并复核用户、平台、频道和频道类型。清理历史后旧来源失效；权限检查仍由既有上下文与历史读取链执行。每个新的用户任务最多检查当前消息及此前 19 条同会话消息，从中选择该用户最新的图片；即使发图时机器人忙碌而跳过唤醒，也能在这个有限窗口内恢复来源。原有缓存存在时也会检查较新的来源。进程重启后沿用同一有限窗口，不会搜索所有旧图。跟踪缓存有固定容量，不保存额外的图片副本。

调试日志中的 `图片上下文` 提供选择数量、生命周期设置、图片上限及排除原因：主视觉开关关闭、组中无视觉模型、生命周期到期、最近图片时间或消息次数到期、数量上限、资源缺失、类型不支持、无效图片数据，以及来源恢复或资源读取失败。日志不包含消息正文、图片 URL、像素数据或原始异常内容。`selected` 表示本次构建的附图数量；资源读取失败仍会按既有请求错误处理，不能据此认为模型已经看到了图片。
