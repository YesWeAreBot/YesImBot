# 上下文与用量查询

这些命令沿用 `history` 的管理员权限，默认查询当前 YIB 实例的全部数据。

## 用量

```text
history.tokens
history.tokens --full
history.tokens --adapter onebot --provider AMD --model example
history.tokens --provider AMD --provider DeepSeek --target onebot:123 --target onebot:private:456
history.tokens --full --page 2
```

筛选参数可以重复：`--adapter`、`--bot`、`--provider`、`--model`、`--target`。
同一类别任一匹配即可，不同类别必须同时匹配。目标支持原始 ID 或 `平台:目标ID`；跨平台同名目标建议写平台前缀。

默认显示范围总量和消耗来源。`--full` 分别按适配器、服务商、模型、目标展开；四类是同一批请求的不同视角，不能再次相加。

- **API**：服务商实际返回的输入 IN、输出 OUT、缓存读取 CR、缓存写入 CW 和总量 Total。
- **Local**：实际请求与响应的文本估算，标记 `≈`；不能准确估计图片、音频等输入时显示未知。
- 默认 `1K = 1000 token`。`—` 表示未知，明确报告零才显示零。
- 缓存用量按接口口径处理，不重复加入 Total。部分请求缺失用量时，只合计已知部分，并列出各字段未知请求数。
- 每次实际请求单独计数，包含重试和错误转移；来源明细的状态表示 HTTP 或响应流的传输结果。
- 未返回用量的流式接口会显示未知。统计不会为了索取用量自动重发请求；可通过服务商支持的自定义请求参数开启流式用量返回。

统计按消耗来源累计保存。正常 Koishi 配置入口重载后会恢复统计；无法识别唯一入口时会明确记录降级，避免不同实例混写。

## 分页

过长结果分为多页。使用相同筛选条件和展示选项，追加 `--page 2` 查看下一页。
查询快照保留五分钟，翻页期间数据不改变；过期或重置后需要重新查询第一页。
完整查询超出容量时会提示缩小筛选范围，不会静默截断正文。

## 重置

```text
history.tokens --reset
history.tokens --restart
```

两个参数作用相同：重置当前实例的全部用量统计并开始新周期，不重启插件，不删除聊天历史或记忆。
不能与筛选、分页或展示参数混用。重置前发出的请求不会计入新周期；旧请求上下文快照同时清除。

## 上下文

```text
history.context
history.context --target onebot:123
history.context --provider AMD --model example --details
history.context --full
history.context --details --page 2
```

默认展示当前实例可见的历史存储概况、核心记忆块，以及最近实际请求的上下文快照。
`--details` 展示完整存储内容和保留的请求上下文，仍通过分页输出。请求中的鉴权头、顶层传输密钥不属于上下文，不展示；消息与工具内容保持原样。查看不会调用模型、触发记忆召回或改变图片生命周期。

旧版历史按平台和目标共享保存，不能准确归属给某个实例或机器人。无法确认可见范围的记录会略过并明确提示。
服务商、模型和机器人筛选作用于实际请求快照，不将共享历史硬归属给某个模型。

请求快照只保留在本次运行的内存中，每个消耗来源保留最近一次请求；最多 128 条、合计 16MiB、单条 2MiB。
超大请求不会保留截断的正文，会明确显示完整内容不可用。长期用量统计不保存请求或响应正文。

## 模型最大上下文

在“服务商 → 模型 → 模型能力”设置最大上下文：

- **未填写**：默认状态，不声明上限，也不自动查询。
- **自定义数值**：接受任意有效正容量和小数，例如 `131072.5`、`131.5K`、`1.25M`；不要求标准档位。
- **auto**：启动后尝试读取该服务商的模型元数据，沿用现有地址、鉴权和代理。

接口未返回明确容量时显示未知，不猜测，也不会覆盖自定义数值。
请求快照中可以查看容量及其来源；查询只读取最近发现结果，不重新发起元数据请求。
当前容量用于配置和观察，不自动裁剪、压缩或清除记忆。
