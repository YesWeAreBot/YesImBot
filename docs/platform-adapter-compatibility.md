# 多平台适配器兼容

YIB 保留适配器的原生频道、群组及引用信息，通过 Koishi 消息编码器发送 XML 元素。QQ 官 Bot 新旧版本与 qq-crack 参见 [QQ 适配器兼容](./qq-adapter-compatibility.md)。

## 线程与目标

| 平台      | 路由与引用                                                                   |
| --------- | ---------------------------------------------------------------------------- |
| Telegram  | 话题 ID 只在所属群内有效；目标同时保留原生群 ID 与话题 ID                    |
| Slack     | 当前线程根据适配器提供的父消息引用继续；显式引用优先，切换目标不继承来源线程 |
| 飞书 Lark | 当前会话保留原生线程 referrer；显式引用交给适配器优先处理                    |
| Discord   | 使用原生线程频道 ID，由适配器处理引用与消息元素                              |
| KOOK      | 使用原生频道及适配器解析的私聊 chat_code                                     |

`send_message` 增加可选 `guild_id`。跨群发送 Telegram 话题时必须提供所属群；未带所属群的其他正整数频道目标会拒绝执行。私聊使用 `target_type: "private"`，经 `createDirectChannel()` 解析。

```json
{ "message": "话题消息", "target": "telegram:42", "guild_id": "-1001234567890" }
```

## 历史与记忆隔离

Telegram 话题的内部频道键为 `telegram-topic:["群ID","话题ID"]`，覆盖历史、上下文、回复调度、暂停规则、延时任务及人物记忆来源。出站前恢复原生 ID，不修改适配器会话。

旧的无群归属话题记录保留，不自动迁入新话题，也不被新话题的读取或清理操作匹配。无法确定所属群的旧来源不会自动用于人物记忆。相同消息在不同机器人上的观察仍可去重，不同群的相同话题和消息 ID 分开处理。

## 媒体与发送保护

- 飞书 `internal:` 资源由 Satori 文件接口处理，保留适配器鉴权及恢复能力，并检查实际内容大小。
- 适配器文件 ID 只有命中本地资源表时才视为本地资源，避免跳过持久化。
- Slack 的 HTTPS `files.slack.com/files-pri/` 附件使用来源机器人的 Bot Token 下载；拒绝重定向，不将凭据或需要鉴权的源地址写入资源元数据。其他域名及路径不附加该凭据。此类私有资源不支持脱离来源鉴权自动恢复。
- 回复取消保护覆盖消息编码器与已知出站接口，包括飞书嵌套消息、图片、文件 API。已经提交给远端的请求无法撤销；适配器持有的其他独立客户端不在此保护范围内。

## 接口参照与验证边界

接口基于 [Satori Koishi 4 分支固定版本](https://github.com/satorijs/satori/tree/7606a0c3bd1ec7756a893bfce4129db9548df213/adapters)下的 Telegram、Slack、Lark、Discord 与 KOOK 源码。插件入口参见 [Koishi 适配器目录](https://koishi.chat/zh-CN/plugins/)。

回归测试覆盖本地 Koishi 编码生命周期、接口契约、资源处理与数据库隔离。远端权限、平台审核及真实账号收发仍需部署环境验证。
