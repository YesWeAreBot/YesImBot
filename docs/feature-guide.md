# 功能与管理入口

YesImBot 的基础对话、回复调度、聊天历史和 L1/L2/L3 记忆由核心插件提供。人物记忆、持久提醒、语音等能力需要另外安装对应扩展；安装扩展不等于已启用其全部功能。

## 按用途查找

| 想做什么                     | 功能归属                   | 入口                                                 |
| ---------------------------- | -------------------------- | ---------------------------------------------------- |
| 连接模型、分配对话与嵌入任务 | 核心：模型服务             | 配置页；`conf.check` 检查引用与声明                  |
| 设置人格与长期核心记忆       | 核心：提示词、核心记忆文件 | 配置页中的提示词与核心记忆路径                       |
| 暂停、恢复回复，查看抑制状态 | 核心：回复管理             | `chat.pause`、`chat.resume`、`chat.status`           |
| 查看为什么回复或保持沉默     | 核心：决策诊断             | `chat.decision`；启用决策记录后使用 `chat.decisions` |
| 查看当前上下文和模型用量     | 核心：请求诊断             | `history.context`、`history.tokens`                  |
| 检索聊天原文、记忆片段或日记 | 核心：历史与记忆召回       | `history.recall`                                     |
| 手动生成长期日记             | 核心：L3 日记              | `history.diary`                                      |
| 统计、清理或备份历史         | 核心：历史管理             | `history.count`、`history.clear`、`history.backup`   |
| 查看、关联和纠正人物身份     | 人物记忆扩展               | `people` 及其子指令                                  |
| 预约、取消或重试提醒         | 持久提醒扩展               | Agent 提醒工具；管理员使用 `reminder` 子指令         |
| 查看与管理模型可调用的工具   | 核心：工具与扩展           | `tool.list`、`tool.info`、`extension.list`           |
| 查询好友、群和群成员名单     | OneBot 名单扩展            | `onebot.contacts` 及其子指令                         |

多数管理指令要求 Koishi 权限等级至少为 3。可用参数以当前安装版本的指令帮助为准。工具是 Agent 可以调用的能力，管理指令是用户在聊天中执行的操作，两者不一定同名或一一对应。

## 几种记忆分别负责什么

| 类型         | 用途                                                       | 设置位置                                 |
| ------------ | ---------------------------------------------------------- | ---------------------------------------- |
| 核心记忆文件 | 保存由文件提供的长期核心信息                               | 核心记忆文件                             |
| L1 工作记忆  | 提供近期消息和 Agent 轮次                                  | 历史记录与上下文 → L1                    |
| L2 记忆检索  | 从保存的片段中找回相关经历；嵌入不可用时提供有界关键词降级 | 历史记录与上下文 → L2                    |
| L3 长期日记  | 按配置的时间、消息阈值或手动操作生成日记                   | 历史记录与上下文 → L3                    |
| 人物记忆     | 保存人物画像、账号关联、来源证据和审核记录                 | 人物记忆扩展；可使用场景模式或共同记忆域 |

关键词降级不能代替嵌入模型的语义匹配能力。`conf.check` 只检查本地配置，不能证明提供商实际支持所声明的能力。

## 看清操作范围

| 操作                                 | 范围与结果                                                                                                                                   |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `history.context` / `history.tokens` | 默认查询当前插件实例；使用筛选参数缩小范围，不能直接当作“当前群统计”                                                                         |
| `history.tokens --reset`             | 重置当前实例全部用量统计并清除旧请求快照，不清除聊天历史或记忆                                                                               |
| `history.recall`                     | 在允许的当前会话检索并注入上下文；默认检索 L3，使用 `-k` 选择消息或 L2，选项放在查询词前；`--display` 会同时把内容发到聊天窗口               |
| `history.clear`                      | 默认清当前频道，可用参数扩大范围；删除消息、系统事件、L2、L3 和匹配的 Agent 日志。共库实例的前四类历史按平台与频道共享，清理会影响其他使用者 |
| `people`                             | 按人物记忆模式作用于当前场景或共同记忆域；纠错或解绑可能影响域内其他关联场景                                                                 |
| `reminder`                           | 仅管理当前机器人与会话的提醒，群聊、私聊及群归属分别核对；清历史不等于取消提醒                                                               |

`history.clear` 不负责清除人物记忆插件的资料、来源与审计、持久提醒或模型用量统计；归属不明的旧 Agent 日志可能保留。需要处理这些数据时，应分别使用对应功能的管理入口。

## 历史备份与恢复

1. 在需要备份的会话执行 `history.backup`，保存返回的备份编号及文件。
2. 恢复前执行 `history.backup.check <id>`，核对缺失记录和冲突。
3. 预检后执行 `history.backup.restore <id>` 恢复指定备份，只补回缺失记录；也可省略编号执行 `history.backup.restore`，默认恢复当前实例、平台、机器人和频道下按备份创建时间排列的最新有效备份。没有可用备份时会提示先执行 `history.backup`。

恢复要求匹配导出实例及平台、机器人和频道归属。相同编号对应不同内容时，预检发现冲突会停止写入。恢复写入失败不保证回滚；先查看回执，再重新预检，确认部分写入情况。

恢复覆盖消息、系统事件、L2 片段和 L3 日记。Agent 日志仅导出和预检，不恢复。备份不包含配置、人物资料、决策日志、用量统计或持久提醒，因此不能用于完整迁移插件或整套 Koishi 环境。

## 持久提醒

持久提醒扩展默认关闭，需要启用并连接可持久保存数据的数据库。到期后，提醒内容会提交给 Agent 处理，由 Agent 决定是否回复；`completed` 表示已提交处理，不是消息送达回执。

进程中断时正在处理的提醒会标记失败，需要管理员核查后显式重试；重试可能重复提交处理。取消无法撤回此前已经提交的处理或已经开始的回复。

详见[持久提醒使用说明](../packages/durable-tasks/README.md)。
