# 会话续接

会话续接用于处理模型明确等待的后续消息。默认关闭；不需要 TypeSafe、JEV 或额外的判断模型。它复用当前会话的工作状态及原始消息来源。

开启后，模型可以通过 `conversation_state_update` 的可选 `followUp` 字段登记等待的用户 ID 和有效时间。非空等待必须引用当前会话中的原始消息，并提交当前 `expectedRevision`。此工具完整替换工作状态；省略 `followUp` 会移除原来的等待。

```json
{
    "expectedRevision": 0,
    "topic": "待确认事项",
    "openIssues": ["等待确认后继续"],
    "sourceMessageIds": ["原始消息ID"],
    "followUp": { "userIds": ["用户ID"], "durationSeconds": 120 }
}
```

用户 ID 应来自当前消息与上下文；登记等待不代表已经确认用户意图。收到指定用户的消息后，明显提及或引用其他人的消息不会命中续接。对于没有显式指向的消息，仍可能出现误接，应由提示词和模型结合上下文决定是否发言、是否移除或调整等待。

## 配置

`continuation` 位于 Agent 的意愿设置中。

| 字段                 | 默认值    | 作用                                                           |
| -------------------- | --------- | -------------------------------------------------------------- |
| `enabled`            | `false`   | 允许登记和使用会话等待                                         |
| `mode`               | `trigger` | `trigger` 进入模型回合；`willingness` 只增加意愿后按原概率判断 |
| `willingnessGain`    | `35`      | 仅增加意愿模式的增益                                           |
| `maxDurationSeconds` | `300`     | 单次登记等待的最长有效时间，范围 1–86400 秒                    |

进入模型回合后仍可保持沉默、调用工具或更新工作状态。会话忙碌时沿用原意愿与调度路径，不额外查询等待状态。续接不绕过频道权限、禁言、回复抑制和新消息处理策略。存在回复抑制规则时不应用续接；规则到期或解除后，仅对之后的新消息重新判断。

## 生命周期与上下文

- 同一实例、平台、机器人账号、频道及频道类型的工作状态分别保存。
- 等待登记后使用固定截止时间；读取和收到消息不会延长等待。等待期间可能多次命中，模型应在等待完成或意图改变后移除或替换它。
- 管理者调低最长等待时间后，已有等待也会受更短的上限约束。
- 状态读取会验证原始来源。来源丢失、内容改变、历史清除或版本替换后，旧等待不能继续作为触发依据。
- 排队后、准备模型上下文时会再次检查等待，仅依赖续接的直接触发模式获准处理的消息在等待到期或被替换后不再执行；本来就符合普通触发条件的消息继续处理。
- 开启续接时，当前有效工作状态关联的原始消息会按需回到本轮上下文。它们是旧来源的临时投影，不写回历史，也不作为新消息或新证据。
- 后台任务完成时，会尽量带回该任务来源消息及其引用。来源不可读取时保留缺失标记，模型可决定重新查询或结束。
- 状态读取失败时回退到普通意愿判断。该功能增加本地状态和来源查询，不新增模型推理请求。

`conversation_focus` 包含有效的工作状态、续接配置及本次命中的来源信息。可以通过现有决策查询查看续接模式和工作状态版本；这些记录不保存原始消息正文。

仅增加意愿模式下，已获得的意愿沿用原有衰减与发言成本规则；等待到期不会收回已经获得的意愿，也不会取消由普通概率判断获准的处理。
