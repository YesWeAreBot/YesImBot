# 命令与意愿评估排查

## 帮助和筛选参数

`-h` 应单独放在完整指令后。不要把它放到需要值的选项后；例如 `history.context --provider -h` 缺少提供商名称。

```text
history.context -h
history.context --adapter onebot --target onebot:857518324
history.context --provider "我的提供商" --model "模型ID" --full
history.tokens --adapter onebot --target onebot:857518324
```

| 参数         | 填什么                             | 示例                                     |
| ------------ | ---------------------------------- | ---------------------------------------- |
| `--adapter`  | 平台名，不是群号或平台与群号的组合 | `onebot`                                 |
| `--target`   | 频道 ID，或包含平台的频道 ID       | `onebot:857518324`                       |
| `--bot`      | 机器人账号 ID                      | 使用实际机器人账号                       |
| `--provider` | 核心配置中的提供商名称             | 使用配置里填写的名称，不是固定的厂商品牌 |
| `--model`    | 提供商的模型 ID                    | 使用实际模型 ID                          |

默认查询整个插件实例。多个不同筛选条件需要同时满足，同一种条件可以重复。提供商、模型和机器人筛选不能给旧的共享历史补上不存在的归属。

上下文请求快照只保留在本次运行中，重启后可能为 0；这不等于聊天历史、画像或用量账本全部丢失。`--details` 会显示完整内容，执行前确认聊天窗口适合展示这些记录。

## 人物查询

`people.show` 接受账号 ID 或人物 UUID，不能用昵称查询。昵称可能重复，也可能与档案中的称呼不同。

```text
people.list
people.show 123456
people.show -h
people.status
```

先执行 `people.list` 获取人物 UUID，再替换 `people.show` 的参数。共同记忆模式下，跨平台账号需保留平台归属，例如：

```text
people.show '["onebot","123456"]'
```

查不到时，核对当前使用的是场景模式还是共同记忆模式，以及共同域是否已改变。切换模式或域名不会自动迁移旧档案。

## 人物记忆配置怎么选

| 配置               | 选择依据                                                                            |
| ------------------ | ----------------------------------------------------------------------------------- |
| 共同记忆开关       | 关闭时按场景保存；开启后可在同一共同域内复用人物认识                                |
| 共同记忆域名称     | 留空按平台与机器人账号区分；需要显式共用人物认识的配置才填写同一个名称，例如 `suni` |
| 回忆范围 `current` | 经历召回只查当前会话；不会使共同域中的人物画像变成独立画像                          |
| 回忆范围 `mind`    | 召回共同域内已有记录且当前配置允许访问的会话；不会自动读取所有群的历史              |
| 后台总结模型组     | 从核心已经配置的模型组列表选择；核心启动或重载后更新列表；留空不会自动调用对话组    |
| 维护模式 `review`  | 后台提出候选，由管理员批准；总结完成不等于画像立即更新                              |
| 维护模式 `auto`    | 允许模型自动维护，仍受来源、版本和锁定约束                                          |

场景旧档案需要通过 `people.import` 显式导入共同域。共享同一域不代表同名账号已被确认成同一个人；账号归属仍需相应证据或管理员关联。

## TypeSafe 和话题分析为什么没有调用

两项功能分别配置。TypeSafe 使用评估模型和 `/systemone` 接口；话题分析使用普通对话模型并要求返回有效话题 JSON，不能只选一处模型就认为两项都已启用。

| 情况                                         | 现有处理                                           |
| -------------------------------------------- | -------------------------------------------------- |
| TypeSafe 为 `off`                            | 不进行语义评估                                     |
| TypeSafe 为 `observe`                        | 发起评估并记录结果，但实际语义倍率为 1，不调整意愿 |
| TypeSafe 为 `adjust`                         | 有效结果用于调整意愿增益                           |
| 话题开关关闭，或未选模型                     | 不发起新话题分析                                   |
| 私聊、明确 @ 机器人、回复忙碌或系统事件      | 跳过新模型评估；部分路径仍可使用已有话题状态       |
| 话题分析间隔或新消息数量未满足               | 复用有效缓存；上次失败时沿用普通意愿               |
| 请求超时、模型不可用、返回结构无效或输入超限 | 沿用普通意愿，不把失败结果当作有效调整             |

在目标群中观察一条没有明确 @ 的普通消息，确认机器人当前没有忙于回复。不要用私聊或连续 @ 作为这两项功能是否运行的唯一测试。

## 按日志判断结果

| 层级    | 用途                                                                                   |
| ------- | -------------------------------------------------------------------------------------- |
| `info`  | 启动时的开关与模型选择摘要；实际评估完成后的耗时、结果倍率、应用倍率和话题倍率         |
| `debug` | 跳过原因、缓存复用、间隔与消息阈值、具体提供商与模型、三项语义得分、实际增益和回复概率 |
| `warn`  | 模型缺失、请求失败、超时、响应结构或输入大小问题，以及沿用普通意愿的说明               |

例如，日志中 `TypeSafe: observe / 结果倍率: 1.500 / 实际应用: 1.000` 表示评估已运行，但处于观察模式。`debug` 中的“意愿增益明细”用于核对倍率是否进入计算，最终是否回复还取决于意愿阈值、概率和回复规则。

这些诊断只记录状态、编号和数值，不需要输出消息正文、模型原始回答或密钥。检查日志设置是否允许对应层级，再按消息 ID、会话与决策 ID 对照查询 `chat.decision` 和 `history.context --trace <决策ID>`。
