# 人物记忆插件（#196）

独立可选的 `koishi-plugin-yesimbot-extension-person-memory`。使用现有 Koishi 数据库，不要求 embedding、RAG 或 Jev。复用 `yesimbot.prompt.inject` 自动提供当前活跃账号的人物关联及画像；不改变核心 L1/L2/L3 或消息 sender。

## 第一版范围

- 场景由 platform、机器人 selfId、群频道或私聊对象组成，账号关联、画像、候选、证据、管理与读取均限制在当前场景；没有跨群入口。
- 账号 ID 精确匹配，昵称仅展示。新账号自动取得独立 UUID 人物，不根据同名或模型猜测合并。管理员可改名、绑定、解绑、合并、拆分。
- 模型只能读取当前场景画像及提出带消息证据的摘要更新，不能修改身份关联或锁定设置。默认 review，支持 off / review / auto，暂停仅阻止自动维护和模型写入，读取仍可用。
- 后台收集受 YIB 频道过滤允许的非机器人消息，按账号批量总结。每场景最多一个任务，全局并发一，队列、输入、输出有界；模型组需显式配置；无配置不调用模型。超时、错误、卸载不得写入迟到结果。
- 候选必须引用插件实际见到的当前场景、当前账号消息。保留账号、原始昵称、消息 ID、时间及有限文本快照；摘要的真实性仍由审核解决。
- 修改使用同一验证与审计机制，接受候选时验证人物、画像及账号关联版本。锁定和人工改动使旧候选失效，防止过期模型覆盖人工结果。
- 关联变更或合并时，受影响已有画像标为需复核，停止进入默认模型上下文，直到管理员修改/重新总结并审核。来源快照不重写。
- 管理命令 authority 3，涵盖查看、解释、修改、身份绑定/解绑/合并/拆分、锁定、候选审批、手工总结、模式/暂停、历史与条件回滚。历史回滚不能静默覆盖后续改动。

## 存储与接入

用场景状态行保存规范化人物、账号和候选，revision 与事务中的条件更新防止丢失更新；另表保存变更差异及证据消息。状态与审计原子写入，版本冲突有限重试。候选上限 50，近期证据上限 200 条/场景，已接受或待审候选的证据快照独立保留在状态/审计中。没有全群预建画像或全量模型名单注入。

上下文最多 6 人、总计 6000 字符，保留 UUID、账号和未知/待复核状态。动态文本要转义 Mustache 与 XML，避免二次渲染或结构注入。`PromptService.inject` 返回可释放注册句柄；旧句柄不能移除同名的新注册。卸载移除工具、注入、计时器并中止后台模型。

已有 OneBot 名单工具继续负责获取群友/好友事实。第一版管理员可以先查询名单，再按账号绑定人物；不自动把名单成员变为画像，暂不增加它的跨插件服务接口。

## 验收

真实 SQLite 验证持久化、同名不同账号、群/私聊/机器人隔离、合并拆分保留消息来源、锁定、旧候选拒绝、审核、并发更新、审计与条件回滚。注册和后台测试验证权限、提案工具限制、注入边界、失败不阻断及卸载后无写入。与改动前的核心测试基线比较，区分原有失败。
